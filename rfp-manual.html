Section 1

How the whole process fits together

An RFP goes from a staff-built draft to a public page venues respond to, then to a scored recommendation for the board. Everything lives at events.clearhq.org. Staff log in; venues never do.

The five pieces

Piece Address (after events.clearhq.org) Who uses it What it is for
Staff RFP form /RFP-form CLEAR staff (login) Build, edit and publish RFPs; keep internal notes; read responses
Public RFP list /rfps Venues, CVBs, anyone Browse open RFPs; filter by city and dates
RFP page /rfps/short-name Venues Read the full requirements, share the link, save a PDF, start a proposal
Proposal form /rfps/short-name/respond Venues Submit one proposal for one RFP
Admin Dashboard /admin-dashboard Planner and administrator (login) Search every proposal, score them, produce the board report

The short-name is created automatically the first time an RFP is set to Open. For example: nrwc-2027-nrwc-annual-conference.

Who can do what

Build and edit drafts Change status Read responses and use the Admin Dashboard Delete an RFP Pick a report due date under 45 days out
Event planner Yes Yes Yes No Yes
Administrator Yes Yes Yes Yes Yes
Other CLEAR staff Yes No No No No
Staff with a @thenrwc.org address (not the planner) NRWC RFPs only No NRWC proposals only No No

Staff who cannot change status still see it as a colored label at the top of the RFP.

The life of an RFP

An RFP is always in one of four statuses: Draft, Open, Closed or Awarded.

  • Draft: staff build it. Anyone with access can edit. The public cannot see it.
  • Open: published on /rfps. Venues can submit proposals. Nobody can edit it, including the planner and administrator.
  • Closed: off the public list. Venues can no longer submit. Locked.
  • Awarded: a venue has been chosen. Off the public list. Locked.

The planner or administrator changes status from a dropdown at the top of the RFP. The dropdown allows any status at any time; the normal path is Draft, Open, Closed, Awarded. To change an Open RFP, set it back to Draft, edit it, save, then set it to Open again. While it is in Draft it is off the public list.

A typical timeline

  1. A staff member or the planner creates the RFP and saves it. Each save emails the planner.
  2. Finish and check the draft against the launch checklist (Appendix C).
  3. Set the status to Open. The public RFP page and proposal form go live.
  4. Tell venues and CVBs (section 6).
  5. Venues respond by the proposal due date, which is 14 days before the report due date you entered.
  6. After the proposal due date, read the responses and score them in the Admin Dashboard (sections 7 and 8).
  7. Set the status to Closed. The system does not do this on its own.
  8. Deliver the board report from the Admin Dashboard by the report due date.
  9. Set the status to Awarded once a venue is chosen.

Getting started

Go to events.clearhq.org/RFP-form and sign in with your CLEAR work email. Your RFP list loads on the left.

Logging in

  1. Open events.clearhq.org/RFP-form in your browser.
  2. Enter your work email. A one-time code is emailed to you.
  3. Type the code. You stay signed in for 24 hours, then you are asked again.
i
Note

If you are told access is denied, your email is not on the approved staff list. Ask the administrator to add it (Appendix D).

The RFP list

The list on the left shows each RFP's group, event name and status.

  • It is sorted by report due date, soonest first. RFPs with no due date appear last.
  • Draft and Open RFPs show by default. Click the Closed or Awarded buttons above the list to include them.
  • Click an RFP to open it. Click + New RFP to start a blank one.
  • Starting a new RFP folds the list away to give you room. Click RFP list at the top of the page to bring it back.

What is on an RFP

At the top of an RFP you see its status. The planner and administrator get a dropdown; everyone else sees a colored label. Below that are four tabs.

Tab What it holds Who sees it
Intake Form Every field of the RFP, plus the Save, Duplicate as New RFP and Delete RFP buttons (Delete is for the administrator only) Everyone with access
Notes Internal, time-stamped comments. They cannot be edited or deleted. Venues never see them. Everyone with access
Version History One entry per save: who saved it, when, and what changed from the previous version Everyone with access
Responses Proposals venues submitted for this RFP (section 7) Planner, administrator, and NRWC staff for NRWC RFPs

Section 3

Creating an RFP

Click + New RFP, fill in the Intake Form, and click Save. Only three fields are required, but every field you fill in is one less question from venues.

Two ways to start

  1. Start blank. Click + New RFP. Pick the Group first so the acronym, website and logo fill in for you.
  2. Copy an earlier RFP. Open it and click Duplicate as New RFP (next to Save). You get a new draft with everything copied except the report due date and event logo, which you must set again. This works on any RFP, even a locked one. Use it for recurring events.

The three required fields are Group, Official Event Name and RFP Response Report Due Date. The form will not save without them. The Intake Form is a set of collapsible panels; only Group Info is open at first, so click a heading to open the others.

Group Info

  • Group: pick from the list (CLEAR, AASCB, CCC, CPE, NASASPS, NRWC). It fills the acronym, website and group logo. NRWC staff see only NRWC.
  • Official Event Name: the name venues see on cards, the RFP page and the proposal form. Use the final name, for example 2028 CLEAR Annual Educational Conference.
  • Group Logo: filled in automatically from the acronym. If the preview says no logo was found, upload one with the file picker. Reset to default logo undoes an upload.
  • Event Logo: optional upload for this event only. It becomes the main image on the card and RFP page. Without it, the group logo is used. When both exist, the page also shows Presented by, with the group logo.
  • Section Priority: rank the sections that matter most for this RFP (1 is most important). Venues never see this. It sets the starting weights when you score proposals (section 8).

Report due date and proposal due date

  • The RFP Response Report Due Date is your internal deadline for having responses compiled into a report. Venues never see it.
  • Venues see a proposal due date that the system sets 14 days earlier. That gives you two weeks to compile.
  • Staff cannot choose a report due date less than 45 days from today (or from the day the RFP was first saved). The planner and administrator can choose any date. This floor is deliberate: because the proposal due date is 14 days earlier, it guarantees venues at least 30 days to respond.

Preferred Cities and Preferred Dates

  • Preferred Cities: up to 5 city options. Enter a city and a rank (1 is the first choice). They appear ranked on the card and RFP page.
  • Preferred Dates: up to 3 date options, each with a start date, end date and rank. When you enter a start date for option 2 or 3, its end date fills in to match option 1's length.
  • If you leave the ranks alone, the public pages list the options as Option 1, Option 2 and so on, in date order.
  • Two checkboxes describe flexibility: the group is open to a different weekday pattern, and the group will not meet on specific days. Use the notes box for specifics, such as must be Mon/Tue.
  • Date Option 1 is the top row, whatever its rank, so enter it first. Its length sets the number of days used by Attendance, Guest Room Needs and Meeting Space Needs.

Attendance

Enter expected attendees for each day. Day rows appear automatically from Date Option 1 (up to 14 days). Peak Attendance is the highest number you enter. The system calculates it and shows it on the card and RFP page. Venues also see the day-by-day table.

Guest Room Needs

  1. Click Auto-generate nights from Date Option 1. It creates one night before, one row per event night, and one night after.
  2. Enter Rooms Needed for each night. Rename a night or change its timing (before, during, after) if needed. + Add night manually adds more.
  3. Enter Max Nightly Room Rate (before tax). This is one ceiling for the whole program, not a rate per night.

Peak Nights is the highest rooms-needed number across all nights. The system calculates it and shows it to venues on the card and RFP page.

Meeting Space Needs

Each room setup is a card. The day buttons on each card come from Date Option 1.

  • Room label, Floor Set, Est. Max Seats: Floor Set options are Classroom, Theater, Banquet Rounds, Crescent Rounds, U-Shape, Reception, Conference / Boardroom and Other.
  • Quantity Needed: if you need 3 of the same room, enter 3 on one card. Do not make three cards.
  • AV Needs: click + Add AV need and pick an item. Quantity starts at 1. AV is counted per room and multiplied by the room quantity. Choose Other to describe anything not listed.
  • Notes and day buttons (Day 1, Day 2, and so on): tick the days the room is needed.
  • Open to colocating: an internal planning question. Venues never see it.
i
Note

These entries matter beyond the RFP page. Venues are asked to match them in the proposal form, and the Admin Dashboard scores that match.

Room templates

Rooms you use again and again can be saved once and reused.

  1. On any room card, click Save as template and name it. It saves the room label, setup, seats, quantity, AV needs and notes. It does not save days.
  2. Next time, use + Add from template… beside + Add room setup. A filled-in card appears. Change the numbers and pick the days.
  3. Saving under an existing name asks before replacing it. Manage templates lists them; the planner and administrator can delete.
i
Note

Templates are shared by all staff. They are copies: editing or deleting a template does not change RFPs that already used it.

Concessions, Food & Beverage, Site Inspection, Exhibits and Budget

  • Must-Have Concessions: add rows and pick from the list (Comp Room Ratio, Staff Room Rate, Comp Suites, Room Upgrades at Group Rate, Airport Transfers, Welcome Amenity, Room Rebate, Comp Staff/Office F&B, Comp Meeting WiFi, Other). Add details in the text box.
  • Food & Beverage: click + Add day for each day (click the day name to rename it). For Breakfast, Lunch and Dinner, tick the service styles you want and mark each Must-have or Nice-to-have. Beverages has its own options, timing (All day, AM only, PM only) and Must-have or Nice-to-have toggle. Add dietary notes at the bottom.
  • Site Inspection: choose Required before contract signing, Desired prior to event (not required before signing), or No site visit needed. Venues are asked how they can support a visit only if one is wanted.
  • Exhibitor & Sponsor Space: tick Exhibits needed, then enter Tables, Booths (10x10 preferred) and the desired placement. Venues are asked where exhibits would go only if this is ticked.
  • Budget: F&B Budget and AV Budget. These are internal only and never shown to venues.

Saving, notes and email alerts

  • Click Save at the bottom. Every save creates a new version you can review in Version History.
  • The form does not save automatically. If you leave the page, unsaved changes are lost.
  • Every save of a draft emails the planner: The proposal for [event name] for [group] has been created or edited and is ready for your review. Many saves means many emails.
  • Duplicating an RFP also sends that email, because it creates a new RFP.

Section 4

Publishing an RFP

Publishing means setting the status to Open. The planner or administrator does it from the status dropdown, and the public page goes live at once.

Before you publish

!
Heads up

Once an RFP is Open, nobody can edit it, so check each item first.

!
Heads up

The system does not check that these are done. It will let you publish an incomplete RFP.

Publishing

  1. Open the RFP and click the status dropdown at the top.
  2. Choose Open. The change saves immediately.
  3. Open events.clearhq.org/rfps and confirm the RFP appears. Click it to check the RFP page.
  4. Click Share this RFP on the RFP page to copy its link, or copy it from the address bar. Send it to venues (section 6).

What locking means

When the status is anything other than Draft, nobody can edit the form, including the planner and administrator. The fields are greyed out and a banner says so. You can still add Notes, read Version History and Responses, and duplicate the RFP.

To make a change:

  1. Set the status back to Draft. The RFP leaves the public list at once, and venues who open the old link are told the RFP is not available.
  2. Edit it and click Save. The planner gets a notification email.
  3. Set the status to Open again. The link is the same as before.
!
Heads up

Avoid editing an RFP after venues have started responding. A venue that already submitted answered the old requirements, and the submission keeps the dates and room counts they saw. If you must change something, tell the venues who have already responded.

!
Heads up

A venue who is partway through the proposal form when you set the RFP to Draft will get an error when they click Submit, and their answers are not saved. Do this only when you must.

Section 5

What venues see and do

Venues need no account. They find an Open RFP on the public list or through a link you send, read it, and submit one proposal through a form. This section describes what they experience, so you can answer their questions.

The public RFP list

Venues see it at events.clearhq.org/rfps. Each Open RFP is a card, with the soonest deadline first.

  • On each card: the logo (the event logo if there is one, otherwise the group logo), group, event name, ranked Preferred Cities, all Preferred Dates, Peak Numbers (Peak Attendance and Peak Nights) and the proposal due date.
  • Filters: venues can filter by city and by a date range. A date range matches an RFP if any of its date options overlaps the range. Clear filters resets them.
  • Draft, Closed and Awarded RFPs never appear here.

The RFP page

Clicking a card opens the full RFP. Venues see these sections, in this order, and any section left empty is hidden: Preferred Cities, Preferred Dates, Attendance, Guest Room Needs, Meeting Space Needs, Must-Have Concessions, Food & Beverage, Site Inspection, and Exhibitor & Sponsor Space.

Three buttons sit on the page:

  • Submit a Proposal (at the top and the bottom) opens the proposal form.
  • Share this RFP copies the page link.
  • Download PDF opens the browser's print window. Choosing Save as PDF makes the file.

Guest Room Needs shows Peak Nights, the max nightly room rate before tax, and a night-by-night table. Meeting Space Needs shows each room with its setup, seats, how many rooms are needed, days and AV needs. AV is listed per room, with a note when a setup is needed in more than one room. The Food & Beverage section includes standard wording that explains the F&B guarantee venues are asked to price: a total price at the stated attendee count, a per-attendee price above it, menu options within 60 days of signing, dietary accommodations, and a note that reception or bar service is priced separately.

i
Note

Venues never see the internal report due date, Section Priority, colocation, the F&B and AV budgets, notes or version history.

If a venue opens the link for an RFP that is not Open, they see: This RFP isn't currently open, or the link is incorrect.

The proposal form

Venues reach it from Submit a Proposal, or at events.clearhq.org/rfps/short-name/respond. A View Full RFP link opens the RFP in a new tab so they can check requirements while they answer. If they try to leave with answers entered, the browser warns them.

Things to know about submissions

  • No edits or withdrawals. A venue cannot change a submission. If they submit again, you see two proposals from the same property. Treat the latest as current.
  • Dates are not enforced. A proposal can arrive with no dates ticked. Check the Dates proposed line in each response.
  • The due date is not enforced. Venues can submit any time the RFP is Open, even after the proposal due date.
  • No alerts. The venue gets no confirmation email, and you get no email when a proposal arrives. Check the Responses tab or the Admin Dashboard.

After they submit

The venue sees: Thank you! Your proposal has been submitted. The event planner will follow up if your property is selected for further consideration. Proposals will not be reviewed until after the proposal due date, followed by that date.

They can click Download PDF of Your Proposal (a summary of their answers, saved through the browser's print window) or Submit a Proposal for Another RFP, which returns them to the list.

What to tell venues and colleagues

Send venues one link and a few lines of instruction. This section gives you copy to paste. Anything in [square brackets] is a blank to fill in before you send.

Instructions to give venues

  1. Open the RFP at [RFP link] and read it in full. No account is needed.
  2. Click Submit a Proposal and complete the form. Fields marked required must be filled in.
  3. For meeting rooms and AV equipment, enter how many of each you can provide in the Qty Available column.

  5. Submit once. A proposal cannot be edited after it is submitted. [Suggested: if you need to correct something, submit again and email clearevents@clearhq.org so we know which one to use.]
  6. Save the PDF of your proposal from the confirmation page for your records.

Invitation email (venues and CVBs)

The proposal due date is shown on the RFP page and the public list. It is 14 days before the report due date you entered.

What to tell colleagues who build RFPs

  • Create the draft and click Save. The planner is emailed on every save, so there is no need to message her separately.

  • Do not ask for edits after publishing unless they are essential. The planner has to set the RFP back to Draft, which takes it off the public list.
  • Rooms you reuse can be saved as templates, so ask the planner what is already saved before building from scratch.
  • Staff with a @thenrwc.org address see only NRWC RFPs.

Section 7

Managing responses

Proposals appear the moment a venue submits. You can read them in two places: the Responses tab on each RFP, and the Admin Dashboard, which spans every RFP. Nothing alerts you when one arrives, so check regularly while an RFP is Open.

The Responses tab (inside an RFP)

The planner, administrator and NRWC staff (for NRWC RFPs) see this tab. Open an RFP and click Responses.

  • One row per proposal: City/State, Property, Room Rate, F&B Minimum, F&B Guarantee (Yes or No) and when it was Submitted.
  • Click a row to expand every answer the venue gave. Links they entered are clickable.
  • Export CSV downloads that RFP's proposals as a spreadsheet. The room and AV answers are included, written as available over needed.

The Admin Dashboard

Open events.clearhq.org/admin-dashboard and stay on Browse Proposals to see proposals from every RFP in one table.

  • Search by property name, city or event name. The Event dropdown narrows the table to one event.
  • Click a column heading to sort by it. Click again to reverse the order.
  • Click a row to expand it. The expanded view includes the room and AV quantities the venue said it can provide, written as available over needed. For example, Breakout Room (2/3) means two available out of three needed. It also shows the details notes the venue wrote under each table.
  • Export CSV downloads the rows the table currently shows, including the room and AV answers.

What to check when you read a proposal

  • Dates proposed. Venues can leave this blank, so confirm each proposal covers dates you can use.
  • Rate and what it includes. Compare the Rate fees included line. A rate that excludes the resort fee is not comparable to one that includes it.
  • F&B guarantee. If the amount is marked exclusive, add the tax and service charge rates the venue listed before comparing it with other proposals.
  • Room and AV match. Look for shortfalls such as 1/3 rooms or 2/6 microphones, and read the details box for the venue's explanation.
  • Cumulative Attrition %. The scoring tool treats a higher percentage as better, on the basis that it is the share of the room block you can release without penalty. Confirm that matches how you read it.
  • Duplicates. The same property twice means it resubmitted. Use the latest.

Known gaps, and what to do instead

  • Proposals cannot be edited or deleted from the screen, including test submissions. Ask the administrator to remove them (Appendix D).

Section 8

Evaluating proposals and reporting to the board

The Admin Dashboard scores every proposal for an RFP against 12 weighted criteria, ranks them, and produces a board-ready report. The weights start from the Section Priority you ranked when you built the RFP, and you can change them. The score is a decision aid, not the decision.

Step by step

  1. After the proposal due date, open events.clearhq.org/admin-dashboard and click Evaluate an RFP.
  2. Choose the RFP from the dropdown. Only RFPs with at least one proposal are listed, with the proposal count.
  3. On the Weights tab, review the starting weights and move any slider (1 is low, 10 is high). Changes save automatically in this browser.
  4. Still on Weights, scroll to Location & Area Fit: Option Values. Set 0 to 10 points for each property type and each area characteristic, based on what matters for this event.
  5. Open the Score Proposals tab. Click each proposal to expand it. For Concessions Quality and CVB Promotions / Incentives, read the venue's text shown above each slider and set a score from 1 to 10.
  6. Click Run Evaluation & See Rankings. The ranking table appears, with the top three highlighted. Click it again after any change to weights or scores.
  7. Open the Report tab. Click Download PDF (in the print window, set the destination to Save as PDF and switch off Headers and footers) or Export as HTML file.

The report is a finished two-page document: a title block with the event logo, summary figures, an executive summary you can edit, the complete rankings, and a side-by-side scoring comparison of the top three proposals. The weights and scoring method are not shown. Click the summary text to rewrite it. Your edits appear in the PDF and are saved in this browser for that RFP, and Reset to suggested text brings back the generated wording.

The 12 criteria and their starting weights

When an RFP ranks the linked section, the weight is 11 minus the rank, so rank 1 gives 10, rank 2 gives 9, and rank 10 gives 1. When the section is not ranked, or there is no linked section, the default weight applies.

Criterion How it is scored Linked Section Priority Default weight

Cumulative Attrition Allowance Relative, higher is better Guest Room Needs 6
Meeting Room Rental Fee Relative, lower is better Meeting Space Needs 5
Room Capacity Match Fulfillment % Meeting Space Needs 8
AV Equipment Match Fulfillment % Meeting Space Needs 6
Meeting Space on One Floor Yes/No Meeting Space Needs 2
F&B Minimum Relative, lower is better Food & Beverage 7
F&B Guarantee Offered Yes/No Food & Beverage 6

How each method scores

  • Relative. Each venue is scored from 1 to 10 against the other proposals for the same RFP. The best figure gets 10, the worst gets 1, and the rest fall in proportion. With rates of $120, $180 and $280, the scores are 10, 6.6 and 1. The tool reads the first number a venue typed, so $189/night counts as 189. If a venue left it blank, or every venue has the same figure, the score is a neutral 5.5.
  • Yes/No. Yes scores 10. No, or blank, scores 4.
  • Fulfillment %. Quantity provided divided by quantity needed, across all rooms (or all AV items). Each line is capped at 100%, so a surplus of one item cannot hide a shortfall in another. The score is 1 plus the percentage times 9. If the RFP had no requirements, or the proposal was submitted before those questions existed, the score is a neutral 5.5.
  • Option-based. A venue's score is the average of the points you set for its property type and the average points for the area characteristics it ticked. Anything unset counts as 5.
  • Manual. You enter the score yourself. It starts at 5.

The total is the sum of each score times its weight, divided by the most it could be, shown as a percentage. Proposals are ranked by that total.

Limits to know before you rely on it

  • Your adjustments live in your browser, not on the server. The starting weights come from the RFP's Section Priority, which is saved with the RFP, so everyone sees the same starting point. Slider changes, Location & Area Fit option values, manual scores and your edited executive summary are saved only in the browser you used. On another computer, or for another person, they start over: weights at the Section Priority starting point, option values and manual scores at 5, and the suggested summary. Clearing browser data erases them. Do the whole evaluation in one browser and export the report when you finish.
  • Rankings are not stored. If you reload the page, run the evaluation again. Export the report to keep a copy.
  • Relative scoring needs at least two proposals. With one proposal, the numeric criteria all come out neutral.
  • Changing Section Priority later does not update saved weights. If you re-rank sections after you have already evaluated an RFP in a browser, click Reset this RFP's weights to Section Priority defaults.
  • Resubmissions count separately. If a venue submitted twice, both proposals are scored. Disregard the older one when you present.
  • Test the result. Move a few weights and run it again. If the top venue changes, say so in your recommendation.
9
Section 9

Closing out an RFP

Close the RFP once the proposal window ends, and mark it Awarded when a venue is chosen. Both are manual steps for the planner or administrator.

Closing

  1. After the proposal due date, set the status to Closed. The RFP leaves the public list, and the proposal form stops accepting submissions.
  2. Responses, Notes and Version History stay available. The Admin Dashboard still lists the proposals and lets you evaluate them.
  3. To take more proposals later, set the status back to Open. The link stays the same. To change the RFP itself, set it to Draft first.

Awarding

  1. When a venue is selected, set the status to Awarded.
  2. Add a Note naming the venue and the date. The system does not record which venue won, and Notes cannot be edited or deleted, so this becomes your permanent record.
  3. Export the board report, and the proposals CSV if you want it, and file them.

Housekeeping

  • Closed and Awarded RFPs are hidden from the RFP list until you click those filter buttons.
  • To start the next edition of a recurring event, open the old RFP and click Duplicate as New RFP. Set the report due date and event logo again.
  • Do not delete an RFP that has proposals. Deleting (administrator only) removes the RFP with its notes and version history, and its public link stops working. The proposals stay in the Admin Dashboard, but the Section Priority is gone, so scoring starts from default weights. Use Closed or Awarded instead.
  • Test proposals cannot be removed from the screen, even if you delete their test RFP. Ask the administrator (Appendix D).

Term Meaning
RFP The published list of what CLEAR needs from a venue for an event

CVB Convention and visitors bureau, a destination marketing organization

F&B minimum The least a group must spend on food and beverage at the venue

Access rules

On both hostnames, these paths require login: RFP-form*, api/whoami, api/rfps*, admin-dashboard* and api/proposals*. These are public: /rfps, /rfps/* and /api/public/*.

  • Keep the Access destination in step with the file name. If it still says proposals* instead of admin-dashboard*, the dashboard page itself is public, although its data stays protected.
  • Room templates live under api/rfps/, so api/rfps* already covers them.

Adding or changing people

  1. Add the person to the Access policy (Zero Trust, Access, Applications) so they can log in.
  2. Add their email to STAFF_DIRECTORY in the API file so their name appears in notes and version history.
  3. Roles are set in the same file: ADMIN_EMAILS (administrator), PLANNER_EMAILS (the planner's three addresses) and DOMAIN_ORG_RESTRICTIONS (thenrwc.org is limited to NRWC). Redeploy after any change.
  4. A new group for the Group dropdown is added to GROUP_PRESETS in the RFP form file. Add its logo to the site root, named ACRONYM-logo.png.

Notification emails

  • Every create or save of an RFP posts the event name and group name to a Power Automate flow named RFP Notification to Candela, which sends the email.
  • The flow's address is the Pages environment variable POWER_AUTOMATE_WEBHOOK_URL (a secret). Changing it needs a redeploy to take effect.
  • The flow's trigger must allow Any caller. The Tenant setting caused 401 errors.
  • Who receives the email, and from which mailbox, is set inside the flow, not in code.
  • A failed notification never blocks a save. If emails stop, check the flow's run history.

Removing test data

Deleting an RFP in the app removes only the RFP record. Its proposals (keys beginning proposal:) and its public link name (slug:) stay until you remove them in the Cloudflare dashboard, under the RFP_DATA namespace.

Known gaps worth fixing

  • Date selection and the proposal due date are not enforced on the proposal form.
  • RFPs do not close automatically at the proposal due date.
  • There is no alert to the planner when a proposal arrives, and no confirmation email to the venue.
  • Scoring adjustments (slider changes, Location & Area Fit option values, manual scores) and the edited executive summary are stored per browser, not on the server. Starting weights do come from the RFP's Section Priority.
  • Proposals cannot be edited, withdrawn or deleted in the app.
